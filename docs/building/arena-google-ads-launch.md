## Conversion definition

- Google Ads action: `Website lead`
- Goal category: Submit lead form
- Optimization: Primary
- Count: One conversion
- Click-through window: 30 days
- Attribution: Data-driven, Google paid channels
- Google tag ID: `AW-740931224`
- Event destination: `AW-740931224/JY4TCOv43c4BEJjtpuEC`
- Transaction ID: the immutable Agent inquiry UUID
- Trigger: Agent has accepted an event or workspace inquiry and returned its
  inquiry UUID. Validation errors, failed requests, and mere button clicks do
  not dispatch the conversion.

The website loads the base Google tag on every page and queues the conversion
event after Agent confirms creation. It also sends Agent an idempotent receipt.
Agent records that receipt as `google_ads_browser_conversion_dispatched` and
labels Google provider acceptance as `not_confirmed`. This deliberately avoids
claiming that Google received or attributed an event when only the browser-side
dispatch is known.

## Attribution and staff evidence

The website preserves first-touch and latest-touch values for `utm_source`,
`utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid`, `gbraid`, and
`wbraid` while visitors move from the Arena page to the inquiry page. Agent
stores the normalized attribution on both the inquiry and its contact.

The Building Sales page shows separate evidence badges:

- **Google click ID captured** means a click identifier reached Agent.
- **Conversion dispatch audited** means the website reported queuing the
  conversion event. It does not mean Google has accepted or attributed it.

## Google-side verification status

Google Ads still showed `Needs attention` / `Tag inactive`, last activity
2025-10-09, and `0.00` attributed conversions immediately after the production
tests. Its setup panel stated that the base Google tag must be activated before
event snippets can measure conversions. The event snippet generated by Google
exactly matched the deployed destination shown above.

The signed-in Chrome profile also displayed Google's `Turn off ad blockers`
warning, and the embedded Google-tag setup panel did not finish loading. A Tag
Assistant attempt from a clean in-app browser opened the domain debug session
but did not connect to the page without the optional extension. Consequently,
Google receipt/attribution remains unproven even though the Anata application
path is proven.

Do not change bidding to Maximize conversions until Google Ads records real
conversion activity and the data is reviewed for lead quality. Google notes
that tag data collection may take up to 30 minutes to begin and conversion
reporting can lag. Recheck the conversion action after processing time.

## Remaining activation action

Use a Chrome profile in which `ads.google.com`, `googletagmanager.com`,
`googleadservices.com`, and `tagassistant.google.com` are allowed. In Google Ads,
open **Goals → Conversion actions → Website lead → Manage → Set up**, finish the
base Google-tag activation/test, and confirm the status changes from `Tag
inactive`. If browser-side delivery remains blocked, provision Google Ads API
OAuth credentials and a developer token before implementing server-side click
conversion uploads; none are currently present in the Agent codebase.
