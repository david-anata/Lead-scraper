# The Arena: how we book an event

For Anata staff. Written 2026-08-01.

## Read this first

Agent will not let you confirm a booking until three things are connected:
a signed agreement, a confirmed payment, and the calendar. **None of those three
is connected yet.** Everything up to that point works today.

That means the process below is real and usable now, with the last two steps
done by hand. Nothing is broken. Agent is refusing on purpose, because a
confirmation it cannot prove is a confirmation we should not send.

**Never tell a customer a date is held until Agent says it is confirmed.**
An inquiry, an estimate, a signature alone, or a payment alone does not hold
the room. This is in our published policy and in the contract, and it is the
one rule that protects us.

---

## The steps

### 1. The inquiry arrives

A customer submits an event inquiry on anatabuilding.com. It appears in
**Agent → Building → Sales**. You will also see it by email, since Building
mail copies David and Val.

Reply the same day. Our published response commitment is four hours.

### 2. Create the booking

**Agent → Building → Bookings → new event reservation.**

Enter the space, the setup start, guest start, guest end, teardown end, and
expected attendance.

Agent refuses attendance above the room's capacity. If it refuses, the number
is wrong or the space is wrong. Do not work around it.

Move the booking to **requirements review**, then to **soft hold** with an
expiry date. A soft hold is internal. It is not a promise to the customer.

### 3. Build the quote

**On the booking, add a quote.**

- Enter the subtotal before any discount.
- If you are discounting, enter the amount and a real business reason. Agent
  refuses a discount with no reason and refuses a discount larger than the
  event. The reason appears on the customer's contract, so write it as you
  would want it read back to you.
- Agent calculates the total, the deposit, and the tax line from the approved
  Arena price list. Do not type the total yourself.

Then move the quote: **approved → sent**. Agent will not let the booking reach
"quote sent" without a real approved, sent quote behind it.

### 4. The customer accepts

When the customer says yes, mark the quote **accepted** on the booking.

A sent quote is locked. If the customer negotiates, create a **new version**
rather than editing the old one. That is deliberate: it keeps a record of what
each party agreed to and when.

### 5. Send the contract

Open the Arena event agreement. Agent fills in the customer, the dates, the
subtotal, the discount and its reason, the total, the deposit, and what is
included.

**Today this is manual:** export it and send it for signature from QuickBooks.
When it comes back signed, record it on the booking with the QuickBooks
reference. Agent will not accept a signed agreement without that proof.

### 6. Collect the deposit

Raise the invoice from the accepted quote. **Do not type the amount.** Use the
option that draws it from the quote, so the discount carries across on its own.

Approve the bill, then send the invoice through QuickBooks.

If Agent refuses with "no longer matches its accepted quote", the quote changed
after the bill was set up. Re-draft the bill from the current quote. That
message is the system stopping you from invoicing a number the customer never
agreed to.

**Today this is manual:** when the payment clears in QuickBooks, record it on
the booking with the payment reference.

### 7. Confirm

Only now. Move the booking to **confirmed**.

Agent checks three things and refuses without any of them:

- a signed agreement with provider proof
- a cleared deposit with payment proof
- a named responsible contact on the booking

When it confirms, tell the customer explicitly. That message is the first time
the date is real.

### 8. Before the event

Confirm the alcohol plan, security, and running schedule **14 days out**. After
that deadline, changes to any of those need written approval.

Balance and the $500 security deposit are due **seven days out**. No access
until everything has cleared.

## When Agent refuses

Agent refusing is almost never a fault. The common ones:

| What you see | What it means |
|---|---|
| Attendance exceeds capacity | The headcount or the space is wrong |
| A business reason is required for every discount | Write why, in plain words |
| The discount cannot exceed the pre-tax subtotal | Check the numbers |
| Only an accepted quote can be billed | Send it and record acceptance first |
| Sent proposal content is immutable | Negotiated? Create a new version |
| No longer matches its accepted quote | Re-draft the bill from the current quote |
| A signed agreement is required | Record the signed contract first |
| A verified deposit is required | Record the cleared payment first |
| A responsible contact is required | Add the named person to the booking |

If you hit something that is not on this list and does not explain itself, stop
and raise it rather than working around it.

## What is not connected yet

Until these land, steps 5 and 6 stay manual and the calendar shows nothing.

1. **The agreement** needs its approval recorded in Agent.
2. **Signing** has no provider connected, so contracts go out of QuickBooks by
   hand.
3. **Payments** have no confirmation feed, so cleared funds are recorded by
   hand.
4. **The calendar** is set up but not switched on, so a confirmed booking does
   not yet appear on anata Events.
5. **The sending address** still needs its domain verified.

When those are done, steps 5 and 6 become automatic and the booking appears on
the calendar on confirmation. Nothing else in this runbook changes.
