# /learn — Learn, Improve & Automate

**Description:** Turn a completed project into a reusable skill or improve an existing one, then evaluate each phase for automation potential. Use after /ship reports complete.

---

## GLOBAL OPERATING RULES

- Think before acting.
- Plan before building.
- Verify before declaring success.
- Never claim completion without evidence.
- Prefer parallel execution whenever tasks are independent.
- Preserve existing functionality unless explicitly instructed otherwise.
- If assumptions are required, state them clearly.
- If a better architecture is discovered during implementation, stop and present it before continuing.
- Optimize for maintainability, scalability, and clarity — not just speed.
- Treat every completed project as an opportunity to improve future workflows and skills.

---

## STEPS 6–8 — Learn, Improve & Automate

Now that implementation is complete, improve future executions.

---

## Step 6 — Build a Claude Skill

Determine whether this conversation represents a repeatable workflow.

If it does:

Create a reusable Claude Skill including:
- Purpose
- When to use it
- Instructions
- Best practices
- Lessons learned
- Common mistakes
- Gotchas
- Future improvements

The goal is to make future executions faster and more reliable.

---

## Step 7 — Improve Existing Skills

If an existing skill was used:

Improve it.

Capture every:
- Edge case
- Failure
- Optimization
- Exception
- Better approach
- Lesson learned

Update the skill so these mistakes never happen again.

Every project should improve future projects.

---

## Step 8 — Evaluate Automation

Only after everything above has been completed:

Evaluate the workflow for automation.

For every major phase perform:

**1. Taste Test**
Does this require human judgment?

**2. 80/20 Test**
Would an 80% solution still be acceptable?

Recommend one of:
- Fully Automate
- Human Assisted
- Never Automate

Explain your reasoning.

Avoid creating unnecessary operational debt.

Prioritize reliability over automation.
